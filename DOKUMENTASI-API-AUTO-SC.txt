DOCUMENTATION API AUTO SC
==========================

Dokumen ini merangkum API yang terpasang di VPS Auto SC.

Komponen API:
1. Core VPS API
   Base URL : https://DOMAIN/vps
   Service  : sc-1forcr-api
   Listen   : 127.0.0.1:API_PORT, diproxy lewat Nginx/Haproxy ke /vps/*

2. Summary API
   Base URL : http://IP_VPS:8789/internal
   Service  : tunnel-summary / Summary API
   Dipakai bot untuk sync, backup, restore, summary akun, dan kontrol tertentu.


AUTHENTICATION
==============

Core VPS API /vps/*
-------------------
Semua endpoint /vps/* wajib memakai token API, kecuali:
- GET /vps/health

Header auth yang didukung:
Authorization: TOKEN
Authorization: Bearer TOKEN

Header opsional untuk menyimpan owner Telegram akun:
x-telegram-user-id: TELEGRAM_USER_ID
x-telegram-chat-id: TELEGRAM_CHAT_ID

Body opsional alternatif owner:
{
  "telegram_user_id": 123456789,
  "telegram_chat_id": 123456789
}

Response sukses standar:
{
  "meta": {
    "code": 200,
    "message": "success"
  },
  "data": {}
}

Response gagal standar:
{
  "meta": {
    "code": 401,
    "message": "unauthorized"
  },
  "message": "unauthorized"
}


Summary API /internal/*
-----------------------
Semua endpoint /internal/* wajib memakai:
x-sync-token: TOKEN

Token valid diambil dari tabel servers kolom key pada database potato.db.

Endpoint yang tidak butuh token:
- GET /health

Response gagal auth:
{
  "ok": false,
  "message": "unauthorized"
}

GET /vps/capacity

Auth:
Authorization wajib.

Fungsi:
- Membaca hasil analyzer resource auto-tune.
- Dipakai untuk melihat apakah server masih aman ditambah user aktif.
- Target default menjaga RAM/CPU tidak melewati 85%.

Response data utama:
{
  "ready": true,
  "capacity_status": "OK",
  "resource_target_percent": 85,
  "ram_total_mib": 961,
  "ram_used_mib": 620,
  "avg_ram_used_percent": 64.5,
  "cpu_used_percent": 12.0,
  "avg_cpu_used_percent": 10.4,
  "cpu_cores": 1,
  "active_connection_count": 24,
  "active_unique_ip_count": 8,
  "active_ssh_user_count": 6,
  "active_xray_user_count": 4,
  "active_user_estimate": 10,
  "active_account_total": 40,
  "capacity_active_user_target": 39,
  "user_ram_estimate_mib": 10.2,
  "user_cpu_estimate_percent": 2.13,
  "can_add_users": 5,
  "recommended_add_batch": 5

Catatan:
- active_user_estimate adalah nilai maksimum dari estimasi koneksi aktif, IP unik, username SSH/dropbear, dan username Xray terbaru.
- recommended_add_batch akan bernilai 5, 2, 1, atau 0 sesuai sisa aman.
- Jika capacity_status FULL/CRITICAL, jangan tambah user aktif dulu.

Buat Akun SSH
-------------
POST /vps/sshvpn

  "password": "pass123",
  "expired": 30,
  "kuota": 100,
  "limitip": 1,

- limitip: limit IP/perangkat, 0 berarti tidak dibatasi oleh field ini

Perpanjang SSH
--------------
POST  /vps/renewsshvpn/:username/:exp
PATCH /vps/renewsshvpn/:username/:exp

Path:
- username: username akun
- exp: tambahan hari

Body opsional:
{
  "password": "pass123",
  "kuota": 200,
  "limitip": 2,
  "recover_missing": true,
  "telegram_user_id": 123456789,
  "telegram_chat_id": 123456789
}

Catatan:
- Jika akun masih ada, expired ditambah dari expired lama.
- Jika akun tidak ada dan recover_missing=true + password ada, akun akan dibuat ulang.
- Jika akun sebelumnya LOCK_QUOTA, unlock hanya berhasil jika kuota baru lebih besar dari pemakaian.
- Field quota yang diterima: kuota, quota, quota_gb, quotaGb.

Cara Hitung Quota SSHWS
-----------------------
Autoscript menghitung pemakaian quota SSH dari beberapa sumber:
- proses SSH/Dropbear user
- counter sesi SSHWS dari mux
- counter runtime quota yang tersimpan di DB

Untuk SSHWS, mux menulis counter traffic ke:
/var/lib/sc-1forcr/sshws-quota.tsv

Checker quota membaca file tersebut sesuai interval:
IPLIMIT_CHECK_INTERVAL_MINUTES

Default interval adalah 3 menit, sehingga pembacaan quota SSHWS bersifat near-realtime, bukan per detik.

Jika IPLIMIT_DEBUG=1, log checker akan menampilkan:
- owner_delta
- proc_delta
- sshws_delta

sshws_delta adalah tambahan pemakaian yang berasal dari jalur SSHWS.

CONTOH CURL
===========

Create SSH:
curl -s -X POST "https://DOMAIN/vps/sshvpn" \
  -H "Authorization: API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"username":"user1","password":"pass123","expired":30,"kuota":100,"limitip":1}'

Create VMess:
curl -s -X POST "https://DOMAIN/vps/vmessall" \
  -H "Authorization: API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"username":"vmess1","expired":30,"kuota":100,"limitip":1}'

Renew SSH:
curl -s -X PATCH "https://DOMAIN/vps/renewsshvpn/user1/30" \
  -H "Authorization: API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"kuota":200,"limitip":2}'

Tambah quota VMess:
curl -s -X PATCH "https://DOMAIN/vps/quota/vmess/vmess1" \
  -H "Authorization: API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"kuota":100,"mode":"add"}'

Summary account:
curl -s "http://IP_VPS:8789/internal/account-summary" \
  -H "x-sync-token: API_TOKEN"

Sync Xray dari Summary API:
curl -s -X POST "http://IP_VPS:8789/internal/sync-xray-from-db" \
  -H "x-sync-token: API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"type":"vmess","restart":true}'


CATATAN KEAMANAN
================

- Jangan expose Summary API ke publik tanpa firewall/IP allowlist. Idealnya bind lokal/VPN saja.
- Simpan API_TOKEN dan x-sync-token secara private.
- Endpoint delete-all, restore-full-backup-url, apply-xray-restart, dan sc-access-lock bersifat sensitif.
- Jika license runtime expired, endpoint /vps/* akan mengembalikan 403 license expired.
- Gunakan HTTPS untuk semua endpoint /vps/* dari bot/client.
- Jangan kirim token lewat query string untuk endpoint publik.
- Rotasi token jika pernah muncul di log, screenshot, atau chat publik.
